# roll · S16 BLG 夺冠纪念版

1. 不采用随机数的方式抽奖；

2. 抽奖截止时间：**待填写**。名单先在本地按完整微信 ID 区分大小写排序，再脱敏并保存到 `roll.js` 的 `userList`。公开代码只保存脱敏名单，并保留原排序，序号从 **0** 开始。参与人数以实际填写为准；

3. BLG 在 S16 全球总决赛决赛中以 **3:1** 战胜 GEN。双方各局击杀数求和后分别加 1，再相乘；

4. 将乘积除以实际参与人数取余，所得余数就是获奖者的序号。

| 局数 | BLG 击杀数 | GEN 击杀数 |
| --- | ---: | ---: |
| 1 | 4 | 19 |
| 2 | 19 | 14 |
| 3 | 20 | 8 |
| 4 | 21 | 11 |
| 合计 | 64 | 52 |

计算公式：`(64 + 1) × (52 + 1) = 3445`。例如 16 人参与时，`3445 % 16 = 5`，即排序后第 6 位参与者获奖。

比赛数据来源：[2026 全球总决赛决赛赛后记录](https://www.reddit.com/r/leagueoflegends/comments/1xwh6et/geng_vs_bilibili_gaming_world_championship_2026/)。

填写名单和截止时间后，在项目目录运行：

```powershell
node .\roll.js
```

脚本末尾会自动调用 `roll()`。输出包含参与人数、按既定顺序排列的两列脱敏名单、每局击杀数、完整计算过程，以及中奖序号和名次，方便截图。名单为空时会提示填写。

`userList` 只保存脱敏 ID，脚本会拦截未脱敏的名单。更新名单时，须先在本地按完整 ID 排序，再脱敏后按原顺序填入；不要把完整 ID 提交到仓库。

**不要对脱敏 ID 再次排序**：星号会改变原有排序，使同一中奖序号对应到不同的人。公开脚本直接使用 `userList` 的既定顺序；本次 26 人，余数为 13，对应第 14 位 `ki******ar`。
